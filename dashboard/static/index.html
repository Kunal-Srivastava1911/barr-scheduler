What this project does

    
Round robin depends on one fixed time quantum. Dynamic quantum algorithms adapt it but assume every burst length is known in advance, which a real operating system does not know. BARR predicts the next CPU burst of each process from its own history and turns the prediction into a bounded per-process quantum.

    
Quantum controller

    
qi = min(qmax, max(qmin, (1 + δ)(pi − ui)))

    
pi is the predicted burst and ui the CPU time already used. When a quantum expires, pi ← max(pi, β·ui), so repeated under-prediction grows the quantum geometrically up to qmax.

    
Algorithm

    
    
      
  1. When a burst becomes ready, build its features from the stored history and predict pi (cold start: exponential average).
    2. 
      
  2. Insert the process in the ready queue: FIFO for BARR, smallest pi − ui first for BARR-S.
    3. 
      
  3. If a waiting process has been passed by more than A dispatches, move it to the head (aging).
    4. 
      
  4. Dispatch the head for qi; charge the switch cost c if it differs from the last process.
    5. 
      
  5. On completion, record the burst and append it to the history; otherwise raise pi and re-queue.
    6. 
    

    
Key observation

    
With exact predictions, FIFO BARR produces exactly the schedule of RR with q = qmax (try BARR-ORACLE against RR-50 in the simulator). A burst prediction is therefore worth more for deciding which process runs next than for how long, which is what BARR-S does.

    
Success thresholds fixed before results

    
    
      
  • Learned predictor reduces MAE by ≥ 15 % relative to exponential averaging.
    • 
      
  • BARR needs ≥ 20 % fewer context switches than the best fixed RR, with P95 response within 10 %.
    • 
      
  • BARR keeps maximum waiting time no worse than RR with q = qmax.
    • 
      
  • Compiled inference of the chosen model takes a few microseconds.
